Graph-based retrieval-augmented generation (GraphRAG) answers questions about a whole document collection by reading summaries of graph communities instead of the graph itself. A large language model writes each summary from a summary input of at most 8,000 tokens, so anything that never reaches an input is lost before a question is asked, and no retrieval method that reads the summaries can recover it. This project measured that loss in Microsoft's GraphRAG 3.1.1 and built a method that repairs it within the same budget.

The loss happens at community boundaries, at the token budget, in the step that chooses which relationships an input may contain, when a large community is summarized from its children's summaries, and for entities that are never clustered. We separate relationships that are out of scope for their own community from relationships whose evidence is absent from every input. Running GraphRAG's own indexing code without a language model on all {NNovels} novels of GraphRAG-Bench Novel, we found that at the default query level the summary inputs keep only {CovCG}% of {NRels} relationships in scope, and that at the root level {AbsAG}% of relationships have no evidence in any input. The standard input builder admits only {SelMin}% to {SelMax}% of within-community relationships, whatever the budget.

We propose Residual Graph Indexing (RGI), which keeps GraphRAG's clustering, summaries and search, and adds an exact record of what the summaries leave out. It spends each input in two tiers, writes bridge records across communities, stores the rest and certifies that every relationship is accounted for. At the same budget and with no extra model calls, RGI raises the in-scope share at the default level from {CovCG}% to {CovCR}% without dropping anything GraphRAG kept. A tested toolkit, the GraphRAG X-Ray simulator and a pre-registered answer-level protocol complete the work.

Keywords: retrieval-augmented generation, knowledge graphs, GraphRAG, community detection, summarization, information loss
